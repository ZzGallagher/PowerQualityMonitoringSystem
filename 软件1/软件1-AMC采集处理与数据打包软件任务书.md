# 软件1：AMC采集处理与数据打包软件任务书

## 1. 文档定位

本文面向轻量版演示系统的软件1开发工作。软件1部署在作为网关的笔记本电脑上，通过 RS485 转 USB 连接一台 AMC 电力仪表，完成数据采集、解析、校验、处理、缓存和数据包发送，为软件2提供真实仪表数据输入。

本任务书依据以下资料整理：

- 《../需求类文档/变电站电能质量监测软件需求分析.md》
- 《../需求类文档/电能质量监测系统项目技术要求.docx》
- 《../参考文档/电能质量项目采集网关设备数据输出内容V1.4.doc》
- 《../参考文档/组态图.pdf》

演示边界：

- 仅接入一个变电站。
- 仅真实采集一台 AMC 电力仪表。
- 不执行真实控制输出，不对现场开关、断路器、UPS、继保、温控设备下发控制命令。
- 未接入设备的状态仅作为组态对象或演示数据，由软件2明确标识为演示/配置态。

## 2. 建设目标

软件1应把一台 AMC 电力仪表包装成轻量级边缘采集网关，实现如下目标：

- 通过串口稳定读取 AMC 仪表数据。
- 将仪表原始寄存器或报文解析成统一电参量数据。
- 对采样数据进行时间戳、单位、倍率、质量码和异常状态标准化。
- 支持实时数据、统计数据、告警事件、通信状态的数据打包。
- 将数据包发送给软件2的数据接收服务。
- 在通信中断或软件2暂不可达时进行本地缓存和补传。
- 提供采集配置、运行状态、日志和调试信息，便于演示现场排障。
- 采用“Python 演示网关 + 可移植 C/C++ 核心边界”的设计，为后续迁移到单片机或嵌入式网关预留路径。

## 3. 技术路线与可移植性设计

### 3.1 当前演示版技术路线

演示阶段的软件1优先采用 Python 编写，目标是快速完成笔记本网关现场联调：

- 语言：Python 3.11+。
- 串口通信：`pyserial`。
- Modbus RTU：优先使用成熟库，例如 `pymodbus`；同时保留最小 Modbus RTU 读寄存器逻辑，便于后续迁移和排障。
- 本地缓存：SQLite 或轻量文件队列。
- 数据上报：HTTP JSON，使用 `httpx` 或 `requests`。
- 配置文件：JSON 或 TOML；第一版直接复用《AMC-E4KC点表-v1.json》。
- 运行形态：先提供命令行程序，后续可封装为 Windows 服务或单文件可执行程序。

演示版开发顺序：

1. 先实现一次性读取工具，读取 AMC 二次侧电参量并打印原始值和换算值。
2. 再实现常驻采集、质量码、缓存和上报。
3. 最后补充运行状态、日志、模拟模式和现场排障能力。

### 3.2 后续单片机迁移原则

为避免 Python 版逻辑无法迁移，软件1从第一版起应按以下分层实现：

- 可移植核心层：Modbus RTU 组帧与 CRC、响应解析、AMC 点表、寄存器换算、质量码、数据包模型。
- 平台适配层：串口读写、时间戳、本地缓存、HTTP/MQTT/TCP 发送、配置读取、日志输出。

后续单片机版本应使用 C99 或 C++11 实现可移植核心层，并替换平台适配层。核心层要求：

- 不依赖操作系统。
- 不依赖动态内存。
- 使用固定缓冲区。
- 点表可由《AMC-E4KC点表-v1.json》生成 C 结构体数组。
- Modbus 读取按固定块执行：`0100H-011BH`、`003FH-0040H`、`008CH-008EH`、`0700H-0701H`、`0022H`。
- 数据包模型应能同时支持 JSON 和后续二进制 TLV/CBOR 等紧凑格式。

演示版 Python 不应把关键换算规则、质量码规则和字段编码散落在业务代码中，应集中放在点表和解码模块中，便于生成或翻译为 C/C++ 实现。

## 4. 运行环境与外设

### 4.1 硬件环境

- 网关主机：Windows 笔记本电脑。
- 采集链路：AMC 电力仪表 -> RS485 总线 -> RS485 转 USB -> 网关主机。
- 目标接收端：软件2后端服务，可与软件1部署在同一台笔记本，也可部署在局域网内另一台主机。

### 4.2 软件环境

- 支持 Windows 10/11。
- 串口驱动支持常见 USB 转 RS485 设备。
- 推荐提供免安装或轻安装交付方式。
- 配置文件采用可读格式，例如 YAML、JSON 或 TOML。
- 本地缓存可采用 SQLite 或轻量文件队列。

## 5. 采集对象与数据项

### 5.1 AMC仪表对象

软件1至少支持配置以下仪表属性：

- 站点编号、站点名称。
- 网关编号、网关名称。
- 仪表编号、仪表名称。
- 仪表型号。
- 串口号。
- 波特率、数据位、停止位、校验位。
- 通信协议，默认按 Modbus RTU 适配设计。
- 从站地址。
- 采集周期。
- 寄存器点表和倍率。

说明：AMC(II)-E4KC 的寄存器地址已依据《../参考文档/AMC(II)-E4KC V1.5-202000811-中文-1.pdf》第 6 章整理为《AMC-E4KC点表-v1.json》和《AMC-E4KC数据字典.md》。第一版采用二次侧寄存器优先口径，使用 Modbus-RTU `03` 功能码只读采集。

### 5.2 必采数据项

根据《../参考文档/电能质量项目采集网关设备数据输出内容V1.4.doc》，AMC 智能电表至少输出以下数据项：

- A相电压值、B相电压值、C相电压值。
- AB线电压、BC线电压、AC线电压。
- A相电流、B相电流、C相电流。
- A相功率、B相功率、C相功率、总有功功率。
- A相无功功率、B相无功功率、C相无功功率、总无功功率。
- A相功率因数、B相功率因数、C相功率因数、总功率因数。
- A相视在功率、B相视在功率、C相视在功率、总视在功率。
- 频率F。
- 吸收有功电能。
- 零序电压、零序电流。
- 电压UA相角、电压UB相角、电压UC相角。
- 电压不平衡度、电流不平衡度。
- 开关量。

### 5.3 扩展预留数据项

为匹配站级需求，软件1的数据模型应预留以下字段，但 AMC 不支持或现场未接入时可为空、模拟或标记为 unsupported：

- 谐波电压、谐波电流。
- 短时闪变、长时闪变。
- 电压暂降、暂升、瞬态事件。
- 三相序分量。
- 断路器分合闸状态、故障脱扣信号。
- 设备故障告警和网络通信告警。

## 6. 功能任务分解

### S1-01 串口与仪表通信

开发内容：

- 枚举本机可用串口。
- 支持串口参数配置和保存。
- 支持手动连接、断开、重连。
- 支持按采集周期轮询仪表。
- 支持通信超时、CRC 错误、非法响应、设备无响应的识别。
- 支持最近一次原始请求/响应报文查看。

验收标准：

- 能通过 RS485 转 USB 读取一台 AMC 仪表。
- 通信中断后界面或日志显示离线状态，并能自动重连。
- 通信恢复后自动恢复采集。
- 串口读写逻辑应隔离为平台适配层，便于后续替换为单片机 UART 驱动。

### S1-02 AMC协议解析与点表配置

开发内容：

- 基于《AMC-E4KC点表-v1.json》建立 AMC 点表配置模型。
- 支持寄存器地址、寄存器长度、数据类型、字节序、倍率、单位、字段编码配置。
- 第一版优先批量读取 `0100H-011BH` 二次侧电参量连续区间，单独读取 `0022H`、`003FH-0040H`、`008CH-008EH`、`0700H-0701H`。
- 将原始值转换为工程值。
- 为每个字段生成质量码：good、timeout、crc_error、parse_error、out_of_range、unsupported。
- Modbus RTU CRC、请求组帧、响应校验、寄存器解码应按可移植核心层组织，避免和 Python 串口库强绑定。
- 点表字段应具备生成 C 结构体数组所需信息：字段编码、地址、长度、数据类型、比例系数、单位、是否启用。

验收标准：

- 点表可配置、可导入、可导出。
- 必采数据项均能映射到统一字段编码。
- 解析错误不导致采集进程退出。
- 解码模块应可以用固定输入寄存器数组做离线单元测试，不依赖真实串口。

### S1-03 数据标准化与派生计算

开发内容：

- 为每个采样值补充采集时间、入库时间、单位、倍率、质量码。
- 计算或归一化总有功功率、总无功功率、总视在功率、总功率因数。
- 支持电压、电流、功率、频率、功率因数、电能、不平衡度的范围校验。
- 支持根据阈值生成越限状态。
- 支持采样值四舍五入和显示精度配置。

验收标准：

- 输出数据字段稳定，不随点表顺序变化。
- 超限、缺测、通信异常能明确标记。
- 时间戳采用统一 ISO 8601 格式。

### S1-04 实时统计与事件识别

开发内容：

- 按 3 秒记录周期生成最大值、最小值、平均值统计。
- 支持实时上传周期配置，默认 3 秒。
- 支持模拟量采集刷新周期不大于 2 秒。
- 支持开关量变化识别，目标刷新周期不大于 1 秒。
- 支持阈值越限告警生成，例如电压越限、电流越限、频率越限、功率因数偏低、三相不平衡超限。
- 支持通信中断告警生成与恢复事件。

验收标准：

- 软件2能收到实时采样包、统计包和告警包。
- 同一告警未恢复前不重复刷屏式生成。
- 告警恢复时产生恢复状态或关闭状态。

### S1-05 数据打包与发送

开发内容：

- 定义统一数据包格式，包含协议版本、包类型、站点、网关、仪表、时间戳、序号和载荷。
- 支持包类型：heartbeat、realtime、statistics、alarm、event、comm_status。
- 支持 HTTP POST 发送到软件2接收接口。
- 支持发送失败重试。
- 支持本地缓存和断点补传。
- 支持数据包签名或简单 token 鉴权预留。
- 数据包构造应先形成平台无关的内部数据模型，再由平台适配层序列化为 JSON；后续单片机版本可替换为二进制 TLV/CBOR 等紧凑格式。

推荐数据包示例：

```json
{
  "protocolVersion": "1.0",
  "packetType": "realtime",
  "sequence": 1024,
  "timestamp": "2026-05-21T14:30:00+08:00",
  "station": {
    "id": "substation-001",
    "name": "演示变电站"
  },
  "gateway": {
    "id": "gateway-001",
    "name": "笔记本网关"
  },
  "meter": {
    "id": "amc-001",
    "name": "AMC智能电表",
    "model": "AMC"
  },
  "points": [
    {
      "code": "ua",
      "name": "A相电压值",
      "value": 220.1,
      "unit": "V",
      "quality": "good"
    }
  ]
}
```

验收标准：

- 软件2接收服务能稳定解析软件1发送的数据包。
- 网络中断时数据不丢失或丢失范围可配置、可提示。
- 数据包字段版本化，便于后续扩展。

### S1-06 本地运行管理

开发内容：

- 提供本地状态页或托盘/命令行状态输出。
- 显示串口状态、仪表在线状态、最近采集时间、发送状态、缓存数量、错误计数。
- 支持启动/停止采集。
- 支持手动发送测试包。
- 支持导出运行日志。
- 支持配置文件热加载或重启后生效。

验收标准：

- 演示现场可快速判断故障位于串口、仪表、协议解析还是软件2接收端。
- 日志包含关键操作、通信错误、发送错误和告警生成记录。

### S1-07 演示与调试辅助

开发内容：

- 提供无仪表模拟模式，用于开发和演示兜底。
- 模拟模式字段与真实数据包完全一致。
- 支持手动触发通信异常、过流、电压越限、三相不平衡等场景。
- 支持录制真实采样并回放。

验收标准：

- 未连接 AMC 时，软件2仍可展示完整演示流程。
- 接入真实 AMC 后，可一键切换为真实采集模式。

### S1-08 可移植核心验证

开发内容：

- 为 Modbus CRC16 提供固定样例测试。
- 为 `uint16`、`int16`、`uint32_be` 等数据类型提供解码测试。
- 为 AMC 点位换算提供离线测试，输入模拟寄存器数组，输出工程值。
- 为质量码判断提供离线测试。
- 为 JSON 点表到 C 结构体数组的生成预留工具或模板。

验收标准：

- 不连接串口也能验证核心解码逻辑。
- Python 演示版与后续 C/C++ 核心使用同一字段编码和同一换算规则。
- 后续迁移到单片机时，只需重写串口、时间、缓存、发送等平台适配模块。

## 7. 数据质量与异常处理

软件1应为每个采样值和数据包标识质量状态：

- good：正常。
- stale：数据未更新但仍在允许时限内。
- timeout：仪表响应超时。
- crc_error：CRC 校验失败。
- parse_error：报文解析失败。
- out_of_range：工程值超出合理范围。
- unsupported：仪表或点表不支持。
- simulated：模拟数据。

异常处理要求：

- 单个点位异常不影响其他点位上报。
- 通信异常不导致程序退出。
- 配置错误应在启动时给出明确提示。
- 本地缓存达到上限时按策略丢弃最旧数据，并记录日志。

## 8. 对软件2接口要求

软件1向软件2发送数据，软件2至少提供以下接口：

- `POST /api/ingest/packets`：接收实时、统计、事件、告警、通信状态数据包。
- `GET /api/ingest/health`：软件1启动前或运行中检查接收端可用性。
- `POST /api/ingest/test`：接收测试包，便于联调。

软件1应支持配置：

- 软件2服务地址。
- token 或接入密钥。
- 发送周期。
- 重试次数。
- 缓存上限。

## 9. 非功能要求

- 模拟量数据更新周期：不大于 2 秒。
- 数字量数据更新周期：目标不大于 1 秒。
- 实时监测上传时间间隔：默认 3 秒，可配置。
- 软件启动时间：普通笔记本上不大于 10 秒。
- 数据发送失败后不阻塞采集线程。
- 配置、日志、缓存文件路径清晰可定位。
- 软件异常退出后再次启动可继续运行。
- 可移植核心层不依赖 Python 专有对象模型，不依赖动态反射，不依赖运行时 JSON 查询。
- 单片机迁移目标下，点表、缓冲区和数据包大小应可静态估算。

## 11. 阶段计划

| 阶段 | 任务 | 输出 |
| --- | --- | --- |
| 第1阶段 | Python 一次性读取工具、点表配置、基础解析 | 能读取 AMC 并输出控制台实时值 |
| 第2阶段 | 可移植核心边界、离线解码测试、质量码 | 解码逻辑可脱离串口测试 |

## 12. 待确认事项

- 串口参数默认值，例如波特率、校验位、从站地址。
- AMC 开关量字段对应的现场含义。
- 软件1和软件2是否部署在同一台笔记本。
- 是否需要把软件1做成 Windows 服务。
- 后续单片机目标型号、RAM/Flash 资源、通信出口方式，例如以太网、4G、Wi-Fi、LoRa 或串口透传。
