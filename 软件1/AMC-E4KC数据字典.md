# AMC-E4KC 数据字典与采集约定

## 1. 采集口径

演示版采用 AMC(II)-E4KC 的 Modbus-RTU 协议，使用 `03` 功能码只读保持寄存器。电参量优先读取二次侧寄存器，避免一次侧 PT/CT 变比在现场联调阶段引入额外不确定性。

AMC 仪表当前不采集谐波相关数据，软件1输出包中不包含 `thd_*` 字段。

## 2. 读取块

| 读取块 | 起始地址 | 数量 | 用途 |
| --- | ---: | ---: | --- |
| 开关量状态 | `0022H` | 1 | `switch_status` DI1业务状态 |
| 吸收有功电能二次侧 | `003FH` | 2 | `ep_import` |
| 电压相角 | `008CH` | 3 | `angle_ua`、`angle_ub`、`angle_uc` |
| 二次侧电参量 | `0100H` | 28 | 电压、电流、功率、功率因数、频率、零序量 |
| 不平衡度 | `0700H` | 2 | 电压/电流不平衡度 |

## 4. 数据包约定

软件1发送给软件2时，每个点位必须使用上表 `code`。点位对象示例：

```json
{
  "code": "switch_status",
  "name": "DI1开关量状态",
  "value": 1,
  "rawValue": 1,
  "unit": "",
  "quality": "good",
  "source": "amc-e4kc-secondary",
  "timestamp": "2026-05-21T14:30:00+08:00"
}
```

质量状态：

- `good`：正常采集并换算成功。
- `stale`：数据超过刷新周期但未超过离线阈值。
- `timeout`：Modbus 请求超时。
- `crc_error`：响应 CRC 校验失败。
- `parse_error`：响应长度、功能码或数据类型解析失败。
- `out_of_range`：换算值超出合理范围。
- `unsupported`：仪表或点表不支持。
- `not_connected`：组态对象未接入真实数据源。

## 5. 现场联调检查单

1. 确认仪表从站地址、波特率、校验位、数据位和停止位。
2. 使用 `AMC-E4KC最小Modbus读取验证.ps1` 先读取 `0100H-011BH`。
3. 将电压、电流、功率、功率因数、频率与仪表屏幕逐项对照。
4. 验证 `0022H`、`008CH-008EH`、`0700H-0701H`、`003FH-0040H`。
5. 对 DI1 做通断测试，确认 `switch_status` 在通路时为 `1`，断路时为 `0`。
6. 若功率单位与仪表屏幕口径不一致，优先修正点表中的展示单位，不修改字段编码。
